# Goal

Implement "The draft of the chat input box will not be automatically cleared after switching to the taskbar and back"
## Inputs
1. Start the server locally: cd web && unset http_proxy && unset_https_proxy && unset_all_proxy && npm install && npm run dev
2. Local test method: Use chrome-devtools mcp to open http://localhost:6152/, use `env:CONDUCTOR_PHONE` to complete the login
3. Start conductor-daemon locally: conductor-daemon --config-file ~/.conductor/config-dev.yaml
## Non-goals
1. Do not implement draft synchronization across devices in this issue
2. Do not save the input content of successfully sent messages
3. Does not change Enter/Shift+Enter behavior
## Steps
1. Use codemap to understand the current code. Focus only on the chat input box state, routing switching, and component uninstallation and reconstruction logic.
2. Design draft persistence strategy:
   - Cache drafts by taskId dimension
   - Restore draft after page switching
   - Clear the task draft after sending successfully
3. Implement store layer support (choose one or a combination of React state/store/localStorage)
4. Add tests:
   - Enter text before jumping and it will still exist after returning.
   - Switch drafts between different tasks without contaminating each other.
   - The draft will be cleared after successful sending.
5. Local manual regression input method, line breaks, undo and other common interactions
## Rules
1. Drafts are only kept in the context of the current user session to avoid aliasing
2. When testing locally, turn off all proxies and then test: unset http_proxy https_proxy HTTP_PROXY HTTPS_PROXY ALL_PROXY all_proxy
3. Component re-rendering should not cause the input to flicker or the cursor to jump.
## Implementation points
1. It is recommended to add `draftByTaskId` status container
2. When restoring a draft, ensure that the value currently being entered by the user is not overwritten.
3. Provide TTL or maximum number of caches to avoid unlimited growth
## Acceptance criteria
1. Return to the taskbar from the chat and then back to the chat, and the draft will be kept intact.
2. Isolation of drafts of different tasks
3. After the message is sent successfully, the input box is empty and the cache has been cleared.
## Risks and rollback
1. Risk: Wrong recovery timing during route switching, resulting in cursor misalignment
2. Rollback: Close draft recovery through configuration, retaining only the status quo behavior
